# Как проверять и запускать

Все команды выполняются в папке проекта `C:\Users\Home\Desktop\genepool edited\GenePool edited`. Оболочка — Git Bash, поэтому пути вида `C:/Users/...` работают.

## Быстрые проверки

| Что проверяем | Команда | Сколько идёт | Что ожидается |
|---|---|---|---|
| Типы TypeScript | `npx tsc --noEmit` | несколько секунд | Вывода нет |
| Сборка | `npx vite build` | около 6 секунд | строка `built in` |
| Сохранение мира, короткий тест | `node tools/save-load-check.cjs --seed 1 --warm 700 --after 100` | около 100 секунд | `B (loading is exact): OK` |
| Сохранение мира, длинный тест | `node tools/save-load-check.cjs --seed 2 --warm 8000 --after 300` | 10–13 минут | то же; запускать в фоне (`run_in_background`) |
| Сохранение мира, с частью A | добавить `--control` | ещё ~10 минут | `A (saving changes nothing): OK` |
| Короткий прогон без браузера | `node tools/headless.cjs --seed 1 --steps 400 --every 200` | около 20 секунд | таблица строк, без `ALERTS` |

Тест сохранения сравнивает хеши всех массивов мира. При расхождении он пишет, на каком шаге и в каких массивах оно появилось. Так найдены все три ошибки этого чата.

## Длинные прогоны (эксперименты)

- Один прогон: `node tools/form-census.cjs --seed 1 --steps 60000 --every 5000 --out tools/results/имя --set "ФЛАГ=значение"`. Около часа на 60 000 шагов.
- `--set` подменяет константы из `Parameters.ts`, например `--set "PREDATOR_VISION_SCALE=1"`.
- Сравнение: `node tools/experiment-compare.cjs tools/results --prefix имя- --at 30000`.
- Хищники по размеру: `node tools/predator-by-size.cjs tools/results --prefix имя-`.
- Серия с контролем: по образцу `tools/run-d19.sh`.
- **Правило проекта:** контроль берётся из того же коммита, что и опыт. Любой новый ген или константа сдвигает случайные числа, поэтому старые прогоны сравнивать нельзя.
- Экологические изменения: сначала короткая проверка, потом несколько одинаковых seed на длинном прогоне (50 000–100 000+ шагов). Так написано в `docs/ТЗ_не_сделано.md`.

## Прогоны владельца в браузере

- Лежат в `runs/<дата>_v<версия>_<бассейн>_<шаги>/`. Сначала читать только `REPORT.md`.
- Версия в имени: `+` — код менялся после коммита; `-dev` — запущено обычным ярлыком.
- Список: `node tools/run-report.mjs runs`.

## Браузер и сервер для своих проверок

- Для своих проверок есть сервер `genepool-dev2` на порту **5199** (`.claude/launch.json`). Запуск: `preview_start` с `name: "genepool-dev2"`.
- **Вкладку владельца на порту 5173 не трогать и не перезапускать.** Сервер 5173 (`Запустить GenePool.bat`) при правках кода показывает плашку «применить, сохранив мир» или «с нуля»; мир сохраняется только по нажатию первой кнопки.
- Сервер 5199 однажды оказался остановлен. Тогда запустить снова.
- Проверки в консоли страницы (`javascript_tool`): симуляция работает в своём потоке, поэтому ждать около 8 секунд после загрузки страницы.
  - `genePool.getTimeStep()` — текущий шаг;
  - `await genePool.request('getSpeciesView')` — виды;
  - `await genePool.saveWorldFile(true)` и `await genePool.loadWorldFile(bytes)` — сохранение и загрузка;
  - `document.getElementById('debugButton').click()` — окно отладки;
  - `document.getElementById('speciesButton').click()` — окно видов;
  - `genePool.startSimulation(SimulationStartMode.NEIGHBORHOOD)` — другой старт.
- В консоли страницы остались старые сообщения `assertion failed: _phenotype.parts[p]...` от загрузок до исправления. Перед выводом смотреть на свежие сообщения (`read_console_messages` с `limit`).

## Грабли, которые уже встречались

1. **Порядок загрузки мира важен.** Сеттеры (`setFoodBitEnergy`, `setHungerThreshold`) меняют все существа и всю еду, поэтому они идут до копирования массивов. Схема в `docs/схема_сохранения_мира.md`, раздел 3.
2. **Новая переменная мира = обновить сохранение.** Если добавляешь поле в `Swimbot`, `GenePool`, `FoodBit`, `Environment`, то добавь его в `saveWorld` / `loadWorld` и в `WORLD_ARRAYS` (или в свой чанк). Иначе тест B упадёт на первом же шаге, как уже было с `deathCause`.
3. **Новорождённый в слоте сбрасывает все служебные поля в `create()`.** Иначе новое существо получает хвост жизни прошлого жильца.
4. **Не использовать `_myGenotype` как временный генотип.** Он может оказаться генотипом чужого существа (так была ошибка загрузки).
5. **`gpRandom()` — единственный источник случайных чисел мира.** `Math.random` в симуляции не использовать (его состояние не сохраняется). Рисование берёт `Math.random`, это нормально.
6. **Параметры из `Parameters.ts` в браузере становятся `let`** (плагин `liveParameters` в `vite.config.ts`). В headless они остаются `const`, и `PARAM_LIST` там пустой. Числа задаются через `--set`.
7. **Окончания строк.** Часть файлов в CRLF, часть в LF. Правки через Python делать с `newline=''`, потом проверять `git diff --stat`, чтобы не получить переписанные целые файлы.
8. **Долгие команды (больше двух минут)** запускать через `run_in_background` и ждать уведомления. Не опрашивать вывод файлом.
9. **Не проверять на глаз то, что не видно.** Например, форма кусков мяса на обычном масштабе не видна. Для этого приближать камеру (`startCameraNavigation(CameraNavigationAction.ZOOM_IN)`).
10. **Смена модели.** Если в этом чате переключают модель, новый ИИ должен прочитать `05_правила_и_общение.md` до первого ответа.
