Порядок внутри каждого раздела — рекомендуемый. Модель и усилие указаны в таблице; владелец может выбрать другие в окне приложения. Крупные механики начинать только после ответа владельца на вопросы ниже.

## Сначала: проверки того, что уже сделано (без вопросов владельцу)

1. **Тест сохранения на текущем коде.** `node tools/save-load-check.cjs --seed 2 --warm 8000 --after 300 --control`, в фоне. Ждём `A ... OK` и `B ... OK`. Если B упал, искать первый расходящийся массив (тест покажет). Причины прошлых падений: новая переменная не сохранена (см. файл 02, грабли 2 и 3).
2. **Визуальная проверка в браузере** (сервер 5199):
   - три кучи при старте (`startSimulation` или обычный старт): видны ли три скопления; при желании сравнить с прошлыми кадрами;
   - куски мяса на сильном приближении: видна ли разница «целый / половина / треть»;
   - перетаскивание строки состояния (`#hud`): работает ли;
   - пресеты отладки: сохранить, загрузить, «по умолчанию».
   Каждый пункт записать как «видно / не видно», с коротким описанием. Скриншоты в ответе владельцу — по желанию.
3. **Многосидовый прогон хищников с ×3 зрением** — по правилу проекта, перед тем как считать изменение полезным. Схема:
   - опыт: `--set "PREDATOR_VISION_SCALE=3"`; контроль: `--set "PREDATOR_VISION_SCALE=1"`, оба на том же коммите `8343de1`;
   - три seed (1, 2, 3), 50 000 шагов каждый (контроль и опыт — шесть прогонов; по часу каждый, можно параллельно при достаточной памяти — проверить);
   - сравнить по `tools/experiment-compare.cjs` и `tools/predator-by-size.cjs`: доля хищников, кто погибает от чего, вымирание хищников.
   Сначала спросить владельца, сколько времени можно потратить на прогоны. Правило: не закрывать пункт после одного прогона.

## Ждёт решения владельца (вопросы — задать по одному, с простыми словами)

Если да — проектировать (Opus xhigh), реализовывать (Sonnet medium).

## Таблица моделей и усилий (сортировка по модели)

Усилия: **low** — механическая работа; **medium** — обычный код по готовому плану; **high** — устройство, ошибка дорогая; **xhigh** — риск сломать симуляцию. **max** не нужен ни для одной задачи.

| задача | идея | модель ИИ |
|---|---|---|
| Формулы в режиме отладки (проект) | Формула текстом, проверка на безопасность, откат при ошибке | Opus 5.5, xhigh |
| Ниши для форм (после согласия) | Разная еда для больших и малых тел, разные места | Opus 5.5, high |
| Мера видов по форме тела | Вид по числу частей, массе, длине, а не по генам | Opus 5.5, high |
| Разбор многосидовых прогонов | Вывод по сравнению с контролем | Opus 5.5, high |
| Круглые диаграммы видов (если нужно) | Круги вместо прямоугольников | Sonnet 5.5, medium |
| Перетаскивание остальных окон | Единый механизм `layout.ts` | Sonnet 5.5, medium |
| Тест сохранения на текущем коде | Части A и B | Sonnet 5.5, low |
| Прогоны хищников ×3 против контроля (3 seed) | Правило проекта: короткая проверка, затем seed | Sonnet 5.5, low |
| Проверка в браузере: кучи, мясо, строка состояния, пресеты | Видно / не видно | Sonnet 5.5, low |
| Перевод вкладки «инфо» (28 страниц) | Черновик, затем проверка владельцем | Haiku 5.5, low |
| Перечитать описания параметров | Поправить формулировки | Haiku 5.5, low |
